## Decision D028 v2 — file-authoritative notes (replaces D028 as drafted)

**Vault md files are the truth. The coordinator stores NO note content.**

- **Rejected (as drafted in `ddf102e`):** coordinator-owned `notes` table with scratchpad as write-through mirror — two masters, Obsidian edits drift, sync hell. User confirmed rejection.
- **Index = a walk, not a table.** Every list/detail request walks the vault tree and builds the index in memory (~131 files, stat+parse = milliseconds). A persistent index table is a deferred optimization ONLY if the walk ever proves slow — it introduces staleness bugs for no current gain. **No schema migration at all.**
- **Ids:** `vault:note:{sha1(relative_path)[:10]}` — deterministic, stable across rescans, opaque (D023: paths NEVER cross the wire; the hash is one-way). Move/rename in Obsidian = old note vanishes + new appears (accepted v1 semantics; no rename/move/delete endpoints).
- **Edits:** `PUT` text write-through to the file + path-scoped git commit (reuse `_git` infra, `src/adapters/vault.py`, W-002). Optimistic lock: client sends `expected_checksum` (sha256 of current file bytes, served on every GET); mismatch → **409 + fresh note body**, client reloads, nothing lost.
- **Index scope (user-confirmed):** `00 - Inbox/`, `scratchpad.md`, `01 - Daily/`, `02 - Projects/`, `03 - Areas/`, `04 - Knowledge/`, `05 - Archive/`. **Exclude** `RepoTasks/`, `06 - Templates/`, `attachments/`, scripts.
- **Project join:** a note under `02 - Projects/<name>/` gets `project_id = vault:project:{slug}` (existing ID space, joins `/v1/projects` — D004). Areas/Knowledge similar (`vault:area:{slug}` if the area space exists, else plain `category`).
- **Frontmatter:** files created BY the system (POST /v1/notes, triage actions) get tiny YAML frontmatter (`title`, `captured`, `source`). The editor treats frontmatter as ordinary text — worst case a user mangles metadata, never content. User-authored files are never modified on read.
- **Changes feed:** notes do NOT join `/v1/changes` in v1 (no persistent rows to version). App refreshes the list on screen entry (cold-flow pull, same as agents). Revisit if it bites.

## Capture pipeline (user-specified)

**Stage = folder location. No status metadata anywhere.**

```
capture (voice/text, quick)          deliberate saves (chat msg, agent result)
        ↓                                        ↓
scratchpad.md                 POST /v1/notes → 00 - Inbox/<date>-<slug>.md
  (## ts — title sections,                      (individual file, uncategorized)
   newest first; pinned note)
        ↓ sorter (rules + tidy), instant-after-capture + 4 sweeps/day
00 - Inbox/<bucket>.md  +  00 - Inbox/unsorted.md
  (one doc per project/area bucket; sections newest-first)
        ↓ EXPLICIT user actions only (phone UI)
02 - Projects/<p>/… · 03 - Areas/… · 04 - Knowledge/…   (long-term, verbatim)
  or → Create task (Vikunja) · Keep (no-op) · Discard (remove section)
```

- **Scratchpad stays** the single quick-capture stream and becomes a first-class pinned note (editable like any other). Per-project scratchpads (e.g. `02 - Projects/Hermes Dual-Bot/scratchpad.md`) are ordinary indexed notes — only the root scratchpad is the sorter's source.
- **Sorter registry** (config `notes.buckets`): bucket key → aliases + keywords (e.g. `kodeverket: [kodeverket, kode, kv, …]`). Match against section text (title weighted). Unmatched → `unsorted.md`. Deterministic rules only — the sorter never decides long-term placement.
- **AI wording contract (binding user directive):** the tidy pass (scratchpad → bucket) may fix ONLY typos, punctuation, whitespace, grammar. It must NEVER merge/drop/reorder ideas, add interpretation, translate, or alter numbers, names, or quotes. Enforced mechanically: after the LLM returns, validators check (a) multiset of digit-runs preserved, (b) word-count ratio within 0.5–2.0×, (c) section title byte-identical. Any violation, LLM error, or timeout → **verbatim move** (the file path is always recoverable in git history — the pre-tidy text lives in the prior commit). Stage-3 filing (inbox → long-term) is ALWAYS verbatim — no AI touches content there.
- **Tidy provider:** same `chat_completion` path as chat (Hermes :8642, claude-sonnet-4). Runs in the fire-and-forget sort pass, so its ~10 s latency never blocks a response. Config `notes.tidy_enabled: true`; flip off = pure verbatim pipeline.
- **Sweep idempotency:** a crash between "append to bucket" and "remove from scratchpad" could double-move. Guard: before appending, scan the bucket for an identical section heading (`## ts — title` is unique per capture) — skip if present, then still remove from scratchpad.
- **Every write is one path-scoped git commit** (`kompakt: …` message prefix), so Obsidian and the phone can never desync, and any action is undoable in git.

### V-060a — walk index, read/edit/create endpoints

**Task 1 — `src/notes.py`: scanner core (pure, no router deps)**
- `scan_notes(cfg) -> list[NoteFile]`: walk include-list dirs (+ root scratchpad), skip excludes; per file: rel path, `id = vault:note:{sha1(rel)[:10]}`, title (first `# ` heading, else filename stem), category (from top folder), project slug (from `02 - Projects/<seg>`), role (`scratchpad` | `inbox` | `note`), mtime, size, sha256, preview (first non-frontmatter non-heading line, ≤120 chars).
- `read_note(id)` / file IO helpers; `_git` commit wrapper reuse for writes.
- Config: new `notes:` section (`para_root`, include/exclude lists, later buckets/tidy/sweeps). Zero-config defaults where possible (mirror `voice:` section style).

**Task 2 — endpoints (src/routers/v1.py)**
- `GET /v1/notes?category=` — real walk; envelope `{"notes": [...]}` (stub already promises the key). Fields: id, title, preview, category, project_id, role, updated_at. NOT full text.
- `GET /v1/notes/{id}` — `{"note": {id, title, text, category, project_id, role, updated_at, checksum}}` or 404. Read file at request time.
- `PUT /v1/notes/{id}` — body `{text, expected_checksum}`; capability `note.write`. Id resolves ONLY via the walk (client paths never accepted — path traversal impossible by construction). Checksum mismatch → 409 `{"detail": "checksum_mismatch", "note": <fresh>}`. Match → write file + scoped commit → 200 fresh note. Text caps mirror W-015 (title 200, body 10 000).
- `POST /v1/notes` — body `{request_id, title?, text, source_type?, source_id?}`; `note.write`; **mutations-ledger idempotency (V-050 pattern — `complete_mutation(db, id, True, result)`, arg-order pitfall)** because it creates external state (file + commit). Creates `00 - Inbox/<yyyy-mm-dd>-<slug>.md` with frontmatter (title/captured/source). 422 empty text; source_type whitelist {chat, agent_run, capture, triage}. Replay → 200 `replayed: true`.
- Flag flip `FEATURES["notes"] = True` (fail-closed §9 for older servers unchanged).

**Task 3 — capabilities**
- Ensure `note.read` in `DEFAULT_DEVICE_CAPABILITIES` (check current list); add `note.write` → phone via admin re-approve with payload rebuilt from the DB row (runbook in skill; per-request DB read → no re-activation).

### V-060b — sorter, tidy, capture hook, sweeps

**Task 5 — section parser + sorter (`src/notes.py`)**
- `parse_sections(md) -> list[Section]` — `## ` headings under the scratchpad; title = heading text minus timestamp.
- `sort_scratchpad(cfg, tidy)`: match sections against `notes.buckets` registry (title-weighted keyword match); move matched → `00 - Inbox/<key>.md` (section prepended, newest-first; file created with `# <Key>` heading on first use), unmatched → `unsorted.md`; dedupe guard (identical heading already in bucket → skip append, still remove); scratchpad rewritten without moved sections; ONE scoped commit for the whole sweep (`kompakt: sort scratchpad → inbox (N sections)`).

**Task 6 — tidy pass (wording contract)**
- `tidy_section(title, text) -> text`: LLM call via existing `chat_completion` provider; prompt encodes the contract verbatim; then validators: digit-run multiset equal, word-count ratio 0.5–2.0, title byte-identical (title is moved verbatim regardless). Any failure → original text. Never applied to inbox → long-term moves.

**Task 7 — triggers**
- Capture note-commit (`_commit_note`): after response, fire-and-forget `asyncio` sort pass (rules + tidy; LLM latency invisible to the client).
- Sweeps 4×/day (~07/12/17/22, config `notes.sweeps`): hook the existing lifespan scheduler loop (verify what `/api/schedule` rebuild uses at implementation; else plain asyncio sleep-until task).

**Task 8 — tests (tests/test_sorter.py, ~10 checks)**
Section parse (empty/edge); rule match + alias; unsorted fallback; move removes from scratchpad (file-level assert); dedupe guard (pre-seeded bucket → no double append, scratchpad still cleaned); tidy validators (mock LLM: good rewrite passes; idea-dropping rewrite rejected → verbatim; LLM exception → verbatim); tidy disabled flag → verbatim; single-commit-per-sweep (git log count); capture E2E on tmp vault: commit note → scratchpad section appears → sort → bucket file + scratchpad clean.

**V-060b close-out:** as V-060a + live capture E2E on the real vault: phone/web capture → scratchpad section → (≤1 min) bucket file section + scratchpad cleaned + one `kompakt:` commit in `git log`.
