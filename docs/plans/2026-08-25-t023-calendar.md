## Locked design decisions (user, Aug 25)

1. **Split screen**: month grid top, agenda for selected day below — single screen.
2. **Entry**: Today date-header tap + More row. **No bottom nav slot** (calendar is enter-with-intent; Today answers "what's next").
3. **Full scope v1**: view + create + edit + delete.
4. **Capture → event**: yes — interpret proposal + explicit confirm.

## Wire contract (depends on V-065)

```
GET  /v1/calendars → {"calendars":[{id, display_name, symbol, writable}]}
GET  /v1/schedule/range?from&to → events tagged {id, calendar_id, title, start_at,
                                     end_at, all_day, location, description, symbol}
POST /v1/events {request_id, calendar_id, title, start_at, end_at|duration_minutes,
                 all_day?, description?, location?} → {id, status}
GET  /v1/events/{id} → event
PATCH /v1/events/{id} → event           DELETE /v1/events/{id} → 204
POST /v1/capture/interpret → proposal may carry {proposed_type:"event",
                                     title, start_at, end_at, all_day, location}
```

Event ids are opaque (`cal:{calendar_id}:{uid}[#occurrence]`) — never parsed client-side.

## T-023a — CalendarScreen (month grid + day agenda)

- Route `CALENDAR` (Routes.all 19 → 20; RoutesTest updated).
- **Month grid**: 6×7 matrix, Monday-first (NO convention), current month label + `‹ ›` arrow nav (no swipe gestures — e-ink, minimal redraw). Selected day = inverse box. Days with events: density mark derived from event count (dot / underline), per-calendar symbol not needed at day level.
- **Data**: one `/schedule/range` fetch per visible month window; calendar picker filters are v2 — all calendars shown, symbol-prefixed.
- **Agenda** (below grid, scrollable): selected day's events — `09:00 ● Philosophy` rows, all-day rows on top (`▪ All day: …`), symbol = calendar. Empty state: "Nothing this day". Persistent `+` action → editor (T-023b).
- **Symbols** from `GET /v1/calendars` (`●` `○` `▪` per registry).
- TodayScreen: date-header row becomes tappable → CALENDAR at today (selected = today).
- `CalendarEvent` domain gains optional `calendar_id`, `symbol`, `allDay`, `description` (additive; Today decode unaffected).
- Fake mode: FakeData multi-calendar events (incl. an all-day + a recurring-expanded pair) + writable/personal + read-only/sa registry so fake mode exercises filters and read-only suppression.

## T-023b — Event detail + editor (CRUD)

- **EventDetailScreen** (read-first, house style): title, time range/duration or all-day, location, description, calendar (symbol + name). Transitions row per object-boundary rule: **[Create task]** (due = start, title prefilled), **[Save note]**. Actions: Edit, Delete (confirm dialog — destructive needs intent on e-ink).
- **Edit/Delete visibility**: ONLY when the event's calendar is `writable` (registry-driven; server enforces anyway — UI just doesn't lie).
- **EventEditorScreen**: shared create/edit form — title, date, start time, duration (or end time toggle), all-day toggle, calendar picker (**writable calendars only** — V-064 lesson: never offer targets the server rejects), location, description. VoiceInput reuse in title + description (mic insert-at-cursor pattern from NoteEditor).
- **Create**: `POST /v1/events` with client UUID `request_id` (retry-safe).
- **Edit**: `PATCH` partial fields; **Delete**: `DELETE` then list refresh. Server-authoritative: after any mutation, re-fetch the month window (no local mirror edits beyond UI state).
- **Reminders**: verify T-020 ReminderPlanner covers multi-calendar merged Today events (should be automatic once V-065a merges reads) — add one planner test with an SA + a personal event.

## T-023c — Capture → event confirm

- Existing capture proposal UI (task/note cards) gains an **event card** when `proposed_type == "event"`: rows for title / date+time / duration / location, all editable before confirm (proposal ≠ command — binding rule).
- Confirm → `POST /v1/events` (calendar = `personal` default; picker honors writable-only) → success feedback "Saved ● <title>".
- Wire decode test: interpret response with event fields renders the card; task/note proposals unchanged (back-compat).
